## Claude (connector directory)

elean is listed in Claude's connector directory, so this is the quickest way to connect from Claude — no URL to paste.

<Steps>
  <Step title="Open the elean listing">
    Go to [claude.ai/directory/elean](https://claude.ai/directory/elean) while signed in to Claude.
  </Step>
  <Step title="Connect">
    Click the connect button on the listing. Claude opens elean's consent screen in your browser.
  </Step>
  <Step title="Sign in and approve">
    Sign in to elean if prompted, pick the workspace the agent gets access to, and approve the connection.
  </Step>
</Steps>

Once approved, elean's tools are available in your Claude conversations. As with every client, a token is scoped to a single workspace — connect again to grant access to another one.

## Connect by URL

For Claude Code and other MCP clients, point the client at the server directly. The server speaks Streamable HTTP at a single endpoint:

```text
https://mcp.elean.app/mcp
```

Every client below discovers OAuth automatically (RFC 8414) and registers itself on first connect (RFC 7591) — no `client_id` or API key to copy anywhere. The first time the client connects, it opens your browser at `elean.app/mcp-connect`, where you approve the connection and pick which workspace the agent gets access to. A token is scoped to a single workspace — connect again to grant access to another one.

### Popular clients

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http elean https://mcp.elean.app/mcp
    ```

    The server requires OAuth before it accepts any request. If elean shows as needing authentication, run `/mcp` in Claude Code and select elean to start the OAuth flow.
  </Tab>
  <Tab title="Claude Desktop">
    The easiest route is the [connector directory](#claude-connector-directory). To add elean as a custom connector instead:

    1. Go to **Settings → Connectors → Add custom connector**.
    2. Name it (e.g. "elean") and paste the URL above.
    3. Click **Add**, then complete the OAuth flow in the browser tab that opens.

    Claude connects to your MCP server from Anthropic's cloud infrastructure rather than your device, so the server must be reachable over the public internet — `mcp.elean.app` already is.
  </Tab>
  <Tab title="Cursor">
    Add to `~/.cursor/mcp.json` (or `.cursor/mcp.json` in a project):

    ```json ~/.cursor/mcp.json
    {
      "mcpServers": {
        "elean": {
          "url": "https://mcp.elean.app/mcp"
        }
      }
    }
    ```

    Cursor prompts you to complete the OAuth flow the first time it connects.
  </Tab>
  <Tab title="Windsurf">
    Add to `~/.codeium/windsurf/mcp_config.json`:

    ```json mcp_config.json
    {
      "mcpServers": {
        "elean": {
          "serverUrl": "https://mcp.elean.app/mcp"
        }
      }
    }
    ```

    Note the field is `serverUrl`, not `url` — Windsurf's config differs from Cursor's here.
  </Tab>
  <Tab title="VS Code">
    Add to `.vscode/mcp.json` in your workspace (or your user profile for a global server):

    ```json .vscode/mcp.json
    {
      "servers": {
        "elean": {
          "type": "http",
          "url": "https://mcp.elean.app/mcp"
        }
      }
    }
    ```

    VS Code uses `servers` as the root key (not `mcpServers`) and requires an explicit `"type": "http"`. MCP tools are only available in Copilot's Agent mode.
  </Tab>
</Tabs>

Any other client that supports OAuth discovery and Dynamic Client Registration should work the same way — point it at the URL above and approve the consent screen when prompted.

## Troubleshooting

<AccordionGroup>
  <Accordion title='"Incompatible auth server" during connection'>
    Your client doesn't support Dynamic Client Registration. Use a client that implements RFC 7591, or reach out for a manually registered `client_id`.
  </Accordion>

  <Accordion title="403 responses from tool calls">
    Check that **AI agent connections** is still enabled in Workspace Settings → Security — disabling it revokes tokens immediately.
  </Accordion>
</AccordionGroup>
